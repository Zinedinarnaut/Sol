# Sol 0.2.1 — Developer Preview

This patch is mainly about setup reliability. It fixes the firmware and fresh
install failures reported after 0.2.0, then cleans up two launcher rendering
regressions found while reproducing them.

## Fixed

- A new Sol data directory no longer reports `Config.json` as missing while the
  bundled engine is creating its default configuration.
- Firmware ZIPs are unpacked into a private, size-limited staging directory
  before LibHac verifies them. This removes the previous large in-memory path
  and gives verification the same filesystem shape as an extracted package.
- The firmware control now has separate native choices for ZIP/XCI packages and
  extracted folders, so Finder actually allows a firmware folder to be chosen.
- Empty packages are rejected before installation. Incomplete archives and
  production keys that do not match the firmware dump now produce a useful
  error instead of exposing a raw filesystem result code.
- The home carousel no longer feeds card geometry back into its own layout on
  every frame. Native scroll snapping remains, and the card border and playtime
  row now fit fully inside the window.
- Sol no longer creates a zero-sized Metal drawable during the first launcher
  layout pass.
- Launch and stop transitions now clamp transient layout sizes, leave macOS in
  charge of fullscreen presentation flags, and use a fresh Metal surface for
  every emulation session.
- The game document types now declare Sol as a Viewer, removing the Launch
  Services warning in packaged builds.

Firmware and production keys must come from the user's own console and should
be dumped from the same system state. Sol does not download either one.

## Still a developer preview

The DMG remains ad-hoc signed and is not notarized. DLSM remains unavailable in
normal public launches while its experimental modes continue developer testing.
