# Sol 0.3.0 — Developer Preview 1

This is a source checkpoint for people following SolMetal or building Sol from
the repository. There is no app or DMG attached to this preview. The current
packaged build remains Sol 0.2.1.

## SolMetal has a real engine path now

SolMetal can now be selected by Sol Engine and carry a game through native
Metal resource creation, shader translation, drawing, presentation, and clean
shutdown. It owns its Metal buffers, textures, samplers, pipelines, and command
queues directly. SPIR-V is translated to Metal Shading Language through a
pinned copy of SPIRV-Cross.

The renderer also has a versioned ABI, cross-context ownership checks, GPU-side
indexed-quad expansion, crop and aspect handling, screenshot readback, and
diagnostic capture tools. Unsupported graphics work stops with an explicit
error instead of quietly dropping back to Vulkan.

This does **not** mean SolMetal is ready to replace the existing renderer. It is
still behind `SOL_METAL_GAL_BACKEND=1`, reports `playable: false`, and the
normal backend remains Vulkan through MoltenVK.

## What was tested

The current M4 test Mac passed:

- the native presentation, resource, compute, raster, shader-cache, teardown,
  AddressSanitizer, UndefinedBehaviorSanitizer, leak, and shared-thread gates;
- 1,440 out of 1,440 repeated stress cycles across 48 renderer contexts;
- 139 Swift tests;
- 15 out of 15 compatibility scenarios, two embedded-host checks, and 11 out
  of 11 visual regression fixtures; and
- a five-title local launch matrix in which every title reached presentation
  and shut down normally.

That last result is lifecycle evidence, not a compatibility percentage. One of
the heavier titles still renders large dark rectangles in a known scene and is
explicitly recorded as not playable. The other matrix runs do not replace
hands-on playthrough testing.

Experimental direct-mutation batching remains off by default. In the measured
scene it saved only two command buffers and one render pass, while the sampled
working set was roughly 485 MiB higher. There was not enough evidence to make
that tradeoff the default.

## Other work in this checkpoint

- A native first-run setup now covers the local profile, optional Apple and
  iCloud features, system files, controller setup, and the game library.
- Profiles gained custom images and generated pixel avatars, play activity,
  captures, Save Vault, game users, and local friends views.
- Sol Cloud gained opt-in, account-scoped backup foundations for portable
  profile data. Apple services still require a correctly provisioned build,
  and friends remain local until a real online provider exists.
- Keyboard state handling and repeated engine sessions were tightened to avoid
  stuck or delayed input after rapid key changes.
- Playtime is checkpointed during a session instead of relying only on a clean
  quit.

## Still experimental

- SolMetal is not the default and is not ready for general gameplay.
- The known dark-rectangle rendering failure is unresolved.
- DLSM remains disabled in public builds.
- This preview has no packaged app.

The current renderer status and reproduction tools are in the
[SolMetal development notes](https://github.com/Zinedinarnaut/Sol/blob/v0.3.0-preview.1/Docs/SOLMETAL.md).
